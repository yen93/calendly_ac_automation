Calendly Lead-Source Sync

Automatic traffic-source capture for new Calendly bookings

Every time someone books a call through Calendly, this automation copies the marketing source behind that booking onto their ActiveCampaign contact, with no manual data entry. It runs by itself every weekday morning, so the team can see where booked leads actually came from.

What it does

When a new Calendly booking comes in, the automation works out which marketing channel the lead came from and records it on the matching ActiveCampaign contact:

  • Reads the new Calendly bookings from the last few days.
  • Figures out the lead’s channel — such as Google Ads, Microsoft Ads, Email or Organic — from the tracking the website attaches to each booking.
  • Finds that person’s ActiveCampaign contact by email, and creates the contact if they aren’t in ActiveCampaign yet.
  • Writes the source onto the contact’s “Src –” fields, but only when the lead-channel field is still empty — so it never overwrites a source that was already recorded.
  • Tags each contact it touches, so you can tell at a glance which ones it created and which it updated.
  • Logs every run to give an auditable history.

How each booking is processed

Each booking follows the same simple set of checks. The key rule is that an existing source is never overwritten — if the contact already has a lead channel recorded, the booking is skipped.

Figure 1 — The decision each Calendly booking goes through.

  • No matching contact → the contact is created from the booking’s name and email, then its source fields are written.
  • Matching contact, lead-channel field empty → the source fields are written (an update).
  • Matching contact, lead-channel field already filled → the booking is skipped to protect the existing source.

The tags it applies

So you can see what the automation did, it tags every contact it writes to:

  • supabase_calendly_ac_automation_new_contact — applied when the automation created the contact.
  • supabase_calendly_ac_automation_update — applied when it updated an existing contact.

Skipped contacts (those that already had a source) are left untouched — no tag, no change.

What it writes to ActiveCampaign

The source is stored on the contact’s “Src –” custom fields:

  • Lead channel, UTM source, UTM medium, UTM campaign and UTM term.
  • The Google Ads click id (gclid) and the Microsoft Ads click id (msclkid), when present.

The lead-channel field is always set; the others are written only when the booking actually carries that value. Landing page, referrer and first-touch fields are left blank, because Calendly doesn’t provide them. The lead channel is decided in this order:

  • Google Ads — a Google click id, or paid Google traffic.
  • Microsoft Ads — a Microsoft click id, or paid Bing traffic.
  • Email — the booking came from an email link.
  • A plain channel label — Organic search, Direct, Referral or AI assistant.
  • Unknown (no tracking) — when the booking carried no source at all.

Where each run is logged

Every run is recorded in two tables, so the results are easy to review:

  • Run summary — one row per run: how many bookings were processed, and how many were created, updated or skipped, plus any flags or errors.
  • Per-booking log — one row per unique booking email (no duplicates), showing the contact, the channel and exactly what happened to it.

When it runs

  • Runs automatically Monday to Friday at 6:00 am Philippine time.
  • Each run looks back over the last three days of bookings, so nothing is missed between runs.
  • It can also be run on demand when needed.

How it's built

The automation is a small cloud function that connects three systems. Nothing runs on anyone’s computer — a scheduler wakes the function each morning, it reads from Calendly, writes to ActiveCampaign, and logs the result to a database.

Figure 2 — The end-to-end pipeline and the role of each component.

The pipeline

  • Scheduler — triggers the function every weekday morning.
  • Edge function (calendly-source-sync) — the brain: it reads bookings, derives the channel, and decides whether to create, update or skip.
  • Calendly — the source of the bookings and their tracking data.
  • ActiveCampaign — where the contact, its source fields and the tags are written.
  • Database tables — where each run and each booking is logged.

Tech stack

  • Supabase Edge Function (Deno / TypeScript).
  • Calendly API (reads bookings and their tracking).
  • ActiveCampaign REST API (creates/updates contacts, writes fields, applies tags).
  • Supabase Postgres database for the run and booking logs.
  • A built-in scheduler that runs the function on a weekday-morning timetable.

Running it manually

Besides the daily schedule, the automation can be run on demand in two modes:

  • Preview (dry run) — shows exactly what it would do — which bookings it found and whether each would be created, updated or skipped — without changing anything in ActiveCampaign.
  • Live run — does the real work: creates and updates contacts, writes the source fields, applies the tags and logs the run.

You can also widen how many days it looks back for a one-off catch-up.
