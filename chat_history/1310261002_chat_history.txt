USER:
"just a question: so this is a newly generated token. does this mean that my old
one no longer works?"

--------------------------------------------------------------------------------
ASSISTANT:
Explained that in Calendly each access token is independent — generating a new one
does not revoke or rotate existing ones; the old token keeps working until it is
explicitly deleted/revoked (or expires). Live proof it still works: the function
is still succeeding on its existing secret (processed bookings as recently as Oct 8;
cron succeeded Oct 11 & 12), which it couldn't if the old token were dead. Caveats:
if the user had explicitly regenerated/revoked the old token it would be dead (not
the case here), and this new file is a separate narrower token (webhooks + org-read,
jti 3604f5e9-...), not a copy of the working one.
